# NextStudio Philosophy

NextStudio is built on a small set of principles. They guide every feature decision, every UI choice, and every release.

## Start making music immediately

NextStudio works out of the box. The first launch must be a working, pleasant experience — before any configuration. Too many open-source applications lose nine out of ten users before the first sound plays, because they require fixing and configuring before they work. That work is ours, not the user's.

## The beginner is the reference

Every UI/UX decision is made with a beginner in mind. Defaults work. Paths are self-explanatory. If a feature needs a manual before it can be found, it is designed wrong.

## Simplicity over feature abundance — implemented means working

What is implemented must work. We prefer less, done completely, over much, done halfway. Several paths to the same goal (toolbar, shortcut, mouse wheel) are welcome — as long as they do not complicate the whole considerably.

## The same experience on every platform

Windows, macOS and Linux (including ARM64) are equal citizens. The experience is the same everywhere — down to someone running the Windows build under Wine on Linux: it should work exactly as it does on macOS. Platform quirks are handled by us, not by the user.

## Openness with respect for what exists

We embrace new ideas, formats and workflows — as long as they do not harm what already works. Innovation without breakage.

## Alpha means early, not sloppy

Alpha software is unfinished — not careless. Milestones, a maintained changelog, tests on all three platforms, and reasoned decisions in the issue tracker: every release carries.

## Open source as attitude, independence as feature

NextStudio is AGPL-3.0. No feature gates, no paid tier, no investor rhythm. Community requests are treated with respect: their original wording is preserved in the issues, even across splits and rejections. What gets built is what music-making actually needs, in the order it is needed.
